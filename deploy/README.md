# Деплой Скетчбука на notes.frosis.kz

Пакет для разворачивания блокнота с рисованием на вашем сервере (frosis.kz,
nginx) с логином и администрированием пользователей — как в File Browser.

## Что внутри

```
frontend/        — готовая production-сборка (HTML/JS/CSS)
server/          — Flask-бэкенд: логин, сессии, CRUD пользователей (SQLite)
deploy/deploy.sh — первичная установка (nginx + systemd + certbot)
deploy/update.sh — быстрое обновление уже развёрнутого приложения
```

Заметки (блокноты/страницы/штрихи/текст/картинки) хранятся **на сервере**,
в той же базе SQLite (`users.db`), что и учётные записи — как в Google
Docs: открыли с любого устройства/браузера под своим логином — увидели
свои же данные. У каждого пользователя данные изолированы на уровне
сервера (проверка `user_id` на каждый запрос), поэтому сброс/очистка
браузера уже не приводит к потере заметок.

**Важно про бэкапы.** Раньше `users.db` содержала только логины и пароли —
потерять её было не страшно. Теперь в ней же лежат ВСЕ блокноты, страницы,
штрихи рисования и вставленные картинки всех пользователей. Обязательно
делайте регулярный бэкап файла `/opt/notes-app/server/users.db` (например,
`cp` по крону в другое место/на другой диск) — если этот файл потеряется
или повредится, данные восстановить будет неоткуда.

## Перед первым запуском

1. **DNS.** Убедитесь, что `notes.frosis.kz` указывает A-записью на IP
   вашего сервера. Домашний IP у вас, по заметкам, меняется при
   перезагрузке роутера — если сервер, на который деплоим, домашний,
   проверьте актуальность записи на Hoster.kz перед запуском certbot
   (иначе он не сможет выпустить сертификат).
2. Скопируйте эту папку целиком на сервер, например:
   ```bash
   scp -r notes-app-deploy user@ваш-сервер:/tmp/
   ssh user@ваш-сервер
   cd /tmp/notes-app-deploy
   ```

## Установка

```bash
sudo bash deploy/deploy.sh
```

Скрипт сам:
- поставит `python3-venv`, `nginx`, `certbot` (если их ещё нет);
- скопирует приложение в `/opt/notes-app`;
- поднимет Flask через `gunicorn` как systemd-сервис `notes-app`
  (слушает `127.0.0.1:8091`, наружу не торчит);
- создаст nginx-сайт для `notes.frosis.kz`, проксирующий на этот порт;
- выпустит HTTPS-сертификат Let's Encrypt и включит редирект на https.

В конце скрипт выведет сгенерированный пароль первого администратора
(логин `admin`) — он же сохраняется в
`/opt/notes-app/server/INITIAL_ADMIN_CREDENTIALS.txt` (права `0600`).
**Смените этот пароль сразу после первого входа** — кнопка с 👤 в шапке
приложения → «Пользователи и аккаунт» → «Сменить свой пароль». После
смены файл с исходным паролем можно удалить.

## Как это работает для пользователей

- Открыли `https://notes.frosis.kz` → редирект на страницу входа.
- Вошли под своим логином/паролем → попали в блокнот, у каждого — свои
  заметки, хранящиеся на сервере (видны с любого устройства/браузера
  после входа под тем же логином).
- Кнопка 👤 в шапке слева — выйти или перейти на страницу аккаунта.
- Кнопка «« над списком блокнотов — скрыть боковую панель (например, для
  просмотра на маленьком экране); стрелка » в левом верхнем углу возвращает
  её обратно. Состояние запоминается в браузере.
- Администраторам там же доступно управление пользователями: добавить,
  сделать/снять админку, сбросить пароль, удалить. Систему нельзя
  оставить без ни одного администратора (сервер сам это блокирует).

## Обновление после новых сборок

Когда пришлю обновлённую сборку — распакуйте её на сервере поверх старой
(или в новую папку) и выполните:

```bash
sudo bash deploy/update.sh
```

Это обновит только `frontend/` и код `server/`, не тронув базу
пользователей и заметок (`users.db`) и секрет сессии (все уже вошедшие
останутся залогинены).

Если в обновлении менялся лимит на размер запроса (`client_max_body_size`
в nginx) или другие серверные настройки вне кода — например, при переходе
на серверное хранение заметок — `update.sh` этого не тронет (он не
трогает nginx). В таком случае разово перезапустите полный
`sudo bash deploy/deploy.sh` — он идемпотентен, ничего не сломает и
подтянет актуальный конфиг nginx.

## Диагностика

```bash
sudo systemctl status notes-app     # статус процесса
sudo journalctl -u notes-app -f     # логи в реальном времени
sudo nginx -t                        # проверка конфига nginx
```

## Если понадобится откатить/удалить

```bash
sudo systemctl disable --now notes-app
sudo rm /etc/systemd/system/notes-app.service
sudo rm /etc/nginx/sites-enabled/notes.frosis.kz /etc/nginx/sites-available/notes.frosis.kz
sudo systemctl reload nginx
sudo rm -rf /opt/notes-app   # удалит и базу пользователей — делайте бэкап users.db, если нужно сохранить логины
```
