# Скетчбук — заметки с упором на рисование

Веб-приложение в духе OneNote, но с акцентом на рисование графическим планшетом
(поддержка давления пера, наклона через Pointer Events API — работает с Wacom и
аналогичными планшетами). Развёрнуто на `notes.frosis.kz`.

## Возможности

- Иерархия **Блокноты → Разделы → Страницы**, как в OneNote (создание,
  переименование, удаление через правый клик).
- Рисование пером с чувствительностью к давлению, маркер (полупрозрачный),
  ластик. Штрихи сглаживаются по сплайну Catmull-Rom — окружности и кривые
  не выглядят гранёными даже при быстром движении.
- Настройка цвета (палитра + произвольный цвет) и толщины линии.
- Undo / Redo (Ctrl+Z / Ctrl+Y), очистка страницы, экспорт страницы в PNG.
- Вставка изображений на страницу.
- Фон страницы: чистый / линованный / клетка / точки.
- Тёмная / светлая / чёрная темы, сворачиваемая боковая панель.
- Векторные (нарисованные, не эмодзи) иконки интерфейса, окрашенные под
  текущую тему.
- Простая защита от касания ладонью: пока пишете пером, случайные касания
  экрана игнорируются короткое время.
- **Хранение на сервере**, не в браузере: логин под своим аккаунтом,
  заметки (блокноты/страницы/штрихи/картинки) доступны с любого устройства
  и не теряются при очистке браузера — как в Google Docs. У каждого
  пользователя данные изолированы на уровне сервера.
- Логин и администрирование пользователей (создание, роль администратора,
  сброс пароля, удаление) — как в File Browser.

## Локальная разработка

```bash
npm install
npm run dev
```

Откройте адрес из терминала (обычно http://localhost:5173) — фронтенд
работает и без бэкенда (упадёт в оффлайн-режим сохранения), но для полной
проверки логина/сервера нужен Flask-бэкенд, см. ниже.

Полный локальный стек (фронтенд + Flask):

```bash
npm run build
npm run preview:full
```

Либо через GitHub Codespaces — уже настроен `.devcontainer/`, полный
предпросмотр (сборка + бэкенд) поднимается автоматически при открытии
Codespace, порт 8091 пробрасывается сам.

## Структура проекта

- `src/types.ts` — модели данных (Notebook/Section/Page/Stroke).
- `src/api/` — клиент серверного REST API (замена IndexedDB).
- `src/draw/` — движок рисования: `CanvasController.ts` (Pointer Events,
  давление/наклон, undo/redo), `render.ts` (отрисовка штрихов переменной
  толщины), `curve.ts` (сглаживание по Catmull-Rom), `background.ts`
  (фоновые паттерны страницы).
- `src/ui/` — `sidebar.ts` (дерево блокнотов), `toolbar.ts` (панель
  инструментов), `account.ts` (аккаунт/выход), `icons.ts` (векторные
  SVG-иконки), `floatingPanel.ts` (позиционирование всплывающих панелей).
- `src/main.ts` — сборка приложения, автосохранение.
- `server/app.py` — Flask REST API: логин, сессии, CRUD пользователей и
  заметок (SQLite, `users.db`).
- `public/` — статические страницы логина и админки.
- `deploy/` — скрипты установки/обновления на сервере (см. ниже).
- `.devcontainer/` — конфигурация GitHub Codespaces.

## Деплой на сервер (notes.frosis.kz)

Внутри `deploy/`:

```
deploy/deploy.sh — первичная установка (nginx + systemd + certbot)
deploy/update.sh — быстрое обновление уже развёрнутого приложения
```

**Важно про бэкапы.** В `users.db` на сервере лежат ВСЕ блокноты, страницы,
штрихи рисования и вставленные картинки всех пользователей, а не только
логины. Обязательно делайте регулярный бэкап файла
`/opt/notes-app/server/users.db` (например, `cp` по крону в другое
место/на другой диск) — если этот файл потеряется или повредится, данные
восстановить будет неоткуда.

### Первичная установка

1. **DNS.** Убедитесь, что `notes.frosis.kz` указывает A-записью на IP
   вашего сервера. Домашний IP может меняться при перезагрузке роутера —
   проверьте актуальность записи на Hoster.kz перед запуском certbot
   (иначе он не сможет выпустить сертификат).
2. Скопируйте проект на сервер (см. «Обновление через git» ниже — так же
   можно и для первого раза) и выполните:
   ```bash
   sudo bash deploy/deploy.sh
   ```

Скрипт сам:
- поставит `python3-venv`, `nginx`, `certbot` (если их ещё нет);
- скопирует приложение в `/opt/notes-app`;
- поднимет Flask через `gunicorn` как systemd-сервис `notes-app`
  (слушает `127.0.0.1:8091`, наружу не торчит);
- создаст nginx-сайт для `notes.frosis.kz`, проксирующий на этот порт;
- выпустит HTTPS-сертификат Let's Encrypt и включит редирект на https.

В конце скрипт выведет сгенерированный пароль первого администратора
(логин `admin`) — он же сохраняется в
`/opt/notes-app/server/INITIAL_ADMIN_CREDENTIALS.txt` (права `0600`).
**Смените этот пароль сразу после первого входа** — кнопка аккаунта в
шапке приложения → «Пользователи и аккаунт» → «Сменить свой пароль».
После смены файл с исходным паролем можно удалить.

### Как это работает для пользователей

- Открыли `https://notes.frosis.kz` → редирект на страницу входа.
- Вошли под своим логином/паролем → попали в блокнот, у каждого — свои
  заметки, хранящиеся на сервере (видны с любого устройства/браузера
  после входа под тем же логином).
- Кнопка аккаунта в шапке слева — выйти или перейти на страницу аккаунта.
- Стрелка над списком блокнотов — скрыть боковую панель (например, для
  просмотра на маленьком экране); стрелка в левом верхнем углу возвращает
  её обратно. Состояние запоминается в браузере.
- Администраторам там же доступно управление пользователями: добавить,
  сделать/снять админку, сбросить пароль, удалить. Систему нельзя
  оставить без ни одного администратора (сервер сам это блокирует).

### Обновление через git (текущий способ)

Репозиторий выложен в GitHub, поэтому обновлять сервер проще всего через
`git pull`, без scp и zip-архивов.

Один раз — клонировать репозиторий на сервер:

```bash
cd ~
git clone https://github.com/Frosis64/sketchbook-repo.git sketchbook
cd sketchbook
```

Если репозиторий приватный, git попросит логин — используйте Personal
Access Token (GitHub → Settings → Developer settings → Personal access
tokens) вместо пароля при первом клоне, дальше git его запомнит.

При каждом обновлении — запушили изменения из GitHub Desktop на
ноутбуке, затем на сервере одна команда:

```bash
cd ~/sketchbook
bash redeploy.sh
```

`redeploy.sh` сам по порядку делает: `git pull` — подтягивает свежий код;
`npm run build` — собирает фронтенд в `dist/`; копирует `dist` в
`frontend` (эту папку ожидает `deploy/update.sh`); затем запускает
`sudo bash deploy/update.sh`, который разворачивает frontend/server в
`/opt/notes-app` и перезапускает сервис, не трогая базу пользователей и
заметок. Спросит пароль sudo, если он не закэширован в текущей сессии.

Это обновляет только `frontend/` и код `server/`, не трогая `users.db` и
секрет сессии (все уже вошедшие останутся залогинены). Если в обновлении
менялись серверные настройки вне кода (например, `client_max_body_size` в
nginx) — `update.sh` этого не тронет (он не трогает nginx). В таком
случае разово перезапустите полный `sudo bash deploy/deploy.sh` — он
идемпотентен, ничего не сломает и подтянет актуальный конфиг nginx.

### Диагностика

```bash
sudo systemctl status notes-app     # статус процесса
sudo journalctl -u notes-app -f     # логи в реальном времени
sudo nginx -t                        # проверка конфига nginx
```

Если сайт не открывается **только из домашней сети** (а с мобильного
интернета всё работает) — это, скорее всего, hairpin NAT: роутер не умеет
заворачивать обращение к своему же внешнему домену обратно внутрь сети.
Ошибка сайта в этом случае не при чём. Обход — добавить в
`C:\Windows\System32\drivers\etc\hosts` строку с локальным IP сервера:

```
ЛОКАЛЬНЫЙ_IP    notes.frosis.kz
```

### Если понадобится откатить/удалить

```bash
sudo systemctl disable --now notes-app
sudo rm /etc/systemd/system/notes-app.service
sudo rm /etc/nginx/sites-enabled/notes.frosis.kz /etc/nginx/sites-available/notes.frosis.kz
sudo systemctl reload nginx
sudo rm -rf /opt/notes-app   # удалит и базу пользователей — делайте бэкап users.db, если нужно сохранить логины
```
